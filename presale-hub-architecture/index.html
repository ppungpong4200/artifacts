เส้นทางของหนึ่งคำถาม

พิมพ์ /ask แล้วเกิดอะไรขึ้นบ้าง กดเล่นเพื่อดูทีละขั้น หรือกดตัวเลขเพื่อข้ามไปขั้นที่ต้องการ

ลูกศรซ้ายขวา เลื่อนขั้น · Home เริ่มต้น · End ขั้นสุดท้าย · Space เล่นหรือหยุด

  1. พิมพ์ /ask คำถามออกจาก Discord เป็นคำสั่งที่เซ็นลายเซ็นแล้ว ถ้าพิมพ์ job:<รหัส> นำหน้า จะต่อบทสนทนาของงานนั้นได้ไม่จำกัดอายุ ไม่มีรหัสจะต่อบทสนทนาเดิมที่เปิดอยู่ภายใน 2 ชั่วโมง interaction → POST /hub/discord
  2. Edge Function ตรวจและรับทราบ ตรวจลายเซ็นและสิทธิ์ผู้ใช้ ตอบ Discord ทันทีว่ารับแล้ว เพราะ Discord รอได้แค่ 3 วินาที จากนั้นสร้าง job ในคิว discord_ask → create_job
  3. งานบางชนิดรอให้กดอนุมัติ งานที่ต้องขออนุมัติจะหยุดรอปุ่ม Approve หรือ Reject ใน Discord ก่อน กด Approve แล้ว job กลับเข้าคิว ส่วนงานถามทั่วไปข้ามขั้นนี้ approvals · ap: / rj: buttons
  4. Worker มารับงาน worker ถาม hub ทุก 10 วินาที เมื่อเจอ job จะรับงานและต่ออายุงานไว้เรื่อยๆ ถ้า worker ตายกลางทาง งานหลุดกลับเข้าคิวและถูกทำเครื่องหมายว่าถูกขัดจังหวะ claim_job · renew_lease
  5. Claude ค้นแล้วเขียนคำตอบ worker เปิด claude -p ในโฟลเดอร์งาน Claude ค้นเอกสารผ่าน hub (ค้นคำและค้นตามความหมาย) แล้วเขียนคำตอบ worker เติมเวลาแก้ไฟล์และลิงก์ Drive ให้ชื่อไฟล์ที่อ้างถึง search_text · related_documents
  6. ส่งคำตอบกลับ Discord worker ส่งผลเข้า outbox ใน hub แล้ว Edge Function โพสต์ลง channel ถ้าส่งไม่ผ่านจะลองใหม่ทุก 30 นาทีนาน 24 ชั่วโมง ค่าใช้จ่ายไม่แสดงใน Discord finish_job → outbox_claim_discord → /hub/send

จากไฟล์หนึ่งไฟล์ เป็น card และ vector

นี่คือสิ่งที่ worker ทำเบื้องหลังทุกชั่วโมง เพื่อให้คำสั่งค้นหาและ /ask มีข้อมูลให้ใช้

ลูกศรซ้ายขวา เลื่อนขั้น · Home เริ่มต้น · End ขั้นสุดท้าย · Space เล่นหรือหยุด

  1. สแกนทุกชั่วโมง worker เดินโฟลเดอร์แล้วเทียบกับ state ในเครื่อง (SQLite) ไฟล์ใหม่หรือที่แก้จะถูกดึงข้อความด้วยไลบรารี ส่วน PDF สแกนและภาพให้ Claude อ่านด้วย vision รอบละไม่เกิน 3 ไฟล์ scan_every_minutes = 60 · vision_per_run = 3
  2. ทำ card ด้วย haiku ข้อความที่ได้ถูกส่งเป็นชุดให้ claude -p ที่ไม่มีสิทธิ์ใช้เครื่องมือ เพื่อสรุปเป็น card หนึ่งใบต่อไฟล์ ไฟล์ที่ไม่ต้องมี card เช่นรูปและสื่อเก็บแค่ metadata card_model = haiku
  3. ส่งขึ้น hub hub รับ card ข้อความที่ใช้ค้น และเวอร์ชันของไฟล์ worker เก็บ state ในเครื่องหลังจาก hub รับแล้วเท่านั้น จึงไม่มีไฟล์ที่ทำเครื่องหมายว่าเสร็จทั้งที่ยังไม่ถึง hub save_card · doc_chunks_put · doc_version_put
  4. ขอรายการที่ยังไม่มี vector หลังรอบสแกนจบ worker ถาม hub ว่า card ไหนยังไม่มี vector hub คำนวณ hash ของ card เอง ทำให้ card ที่แก้แล้วถูกทำใหม่ และเปลี่ยนโมเดลแล้วทำใหม่ทั้งชุดได้ doc_embedding_todo
  5. แปลงเป็น vector บน CPU multilingual-e5-small รันใน process แยกบน CPU ของเครื่อง ไม่เสีย token วัดได้ 35 ถึง 59 card ต่อวินาทีบนเครื่องนี้ ผลลัพธ์ 384 มิติเก็บใน pgvector doc_embeddings_put
  6. ใช้งานจริง /find ค้นคำในข้อความเต็ม (ภาษาไทยตัดคำที่เว้นวรรค) ส่วน /related ใช้ vector หาเอกสารที่ความหมายใกล้กัน และ vault ใช้ vector เดียวกันสร้างลิงก์ความเกี่ยวข้องในโน้ต search_text · related_by_name · vault_tick
